# Gesture Christmas Tree

一个用摄像头手势控制的 3D 圣诞树 —— [ai-camera](../../README.md) 里的第一个 Task，
Nex Playground 风格的体验。
手势识别和渲染全部在浏览器本地完成，画面不会离开你的设备。

```bash
cd projects/christmas-tree
npm install     # 顺带把 MediaPipe wasm 运行时同步到 public/wasm
npm run dev     # 打开 http://localhost:5173
```

点击「开启摄像头」，把手举到镜头前，看到骨架出现就可以开始。

> 手机访问：`npm run dev:https`，然后用手机打开终端里打印的 `https://<你的内网IP>:5173`
> （getUserMedia 在非 localhost 的 http 下会被浏览器拒绝）。首次需要信任自签名证书。

## 手势对照表

| 手势 | 效果 |
| --- | --- |
| 张开手掌（保持 ~1.2s） | 种下圣诞树，从地面生长出来 |
| 捏合 → 移动 → 松开 | 在手的位置挂一个装饰球（捏得越紧球越小） |
| 胜利手势 ✌️（保持 ~1s） | 树顶放上发光的星星 |
| **单手**竖起拇指 👍（保持 ~0.7s） | 开 / 关缠绕的彩灯 |
| 张开手掌，左右移动（单手或双手都行） | 转动圣诞树（可以一直转圈） |
| 双手张开手掌，分开 / 靠近 | 放大 / 缩小圣诞树 |
| 食指指向 | 指尖撒出魔法亮粉 |
| **食指在空中划一道弧** | 树后出现一道彩虹，停 5 秒后慢慢消失 |
| **双手都伸出三指**（保持 3s） | 清空场景：装饰球 / 星星 / 彩灯 / 所有礼物 / 彩虹，只剩一棵树（**墙上照片保留**） |
| **双手拍手** 👏 | 暴雪 + 漫天礼物砸下来 + 放烟花 |
| **竖起小拇指**（保持 ~0.9s） | 圣诞老人驾驯鹿车走一个 S：先从树后飞过，绕出画面再从树前贴近掠过，然后离开（带雪橇铃音效） |
| **双手**竖起大拇指 👍👍 | 屏幕倒数 3、2、1，自动拍照，照片随机贴到背景墙上 |
| 双手食指同时指向（保持 ~1.8s） | 重置场景（也可以按 `R`） |
| **鼠标**拖动画面 / 滚轮 | 转动 / 缩放圣诞树 |
| 键盘 `4` `1` `2` `3` `5` `6` | 没摄像头时的替身键：种树 / 拍手 / 清空 / 圣诞老人 / 彩虹 / 拍照 |
| 右上角 ♪ 按钮 | 开 / 关背景圣诞音乐 |

左上角的 HUD 会实时显示两只手识别到的手势，当前可用的操作会高亮；
需要「保持」的手势会在屏幕中央画一个进度环。

## 实现结构

```

  vision/

    handTracker.ts         MediaPipe HandLandmarker 封装，输出已镜像的 21 个关键点
  gestures/
    recognizer.ts          关键点 → 单手手势分类 + 时间平滑 / 防抖

  scene/
    stage.ts               渲染器、灯光、环境、Bloom 后处理
    tree.ts                程序化生成的冷杉 + 自下而上的生长动画
    ornaments.ts           装饰球（InstancedMesh，飞向树面并吸附）
    fairyLights.ts         螺旋彩灯 + 闪烁
    star.ts                树顶星星（倒角挤出几何 + 光晕 + 点光源）
    gifts.ts               地面上的礼物盒（礼盒 + 丝带 + 蝴蝶结）
    giftRain.ts            从天上砸下来的礼物雨（翻滚 + 落地弹跳 + 躺平）
    fireworks.ts           烟花：升空的礼花弹 + 炸开的闪烁火星
    santa.ts               圣诞老人 + 三头驯鹿 + 雪橇，沿 S 形曲线穿过场景
    rainbow.ts             树后的彩虹（半环 + 径向着色，渐显 → 停 5s → 渐隐）
    photoWall.ts           背景墙 + 随机钉在墙上的照片（8 张，满了复用最旧的）
    effects.ts             飘雪（可以被拍手「加大」）、亮粉粒子
  ui/
    hud.ts                 HUD / 中央提示 / 进度环
    handOverlay.ts         摄像头小窗上的手部骨架
    pointerControls.ts     鼠标拖动 / 滚轮
  scripts/
    sync-wasm.mjs          postinstall：把 MediaPipe wasm 运行时同步进 public/
public/
  models/                  MediaPipe .task 模型（已提交进仓库，离线可用）
  wasm/                    MediaPipe 运行时（不提交，由 postinstall 生成）
```

**为什么 models 提交、wasm 不提交。** `public/wasm` 是
`node_modules/@mediapipe/tasks-vision/wasm` 的逐字节拷贝。提交它的话，以后升级
`@mediapipe/tasks-vision` 这份拷贝会静默过期 —— wasm 运行时和 JS 封装版本不一致，
在加载时报的错非常难查。交给 `postinstall` 同步，两者就天然锁在一起。
`.task` 模型相反：它们按 URL 锁定到某个具体模型版本，不会和 npm 包产生版本漂移，
提交进仓库则意味着全新 clone 下来**不需要联网**就能跑。

### 几个关键设计

**镜像与坐标。** 摄像头预览做了水平镜像（符合照镜子的直觉），所以
`handTracker` 直接把关键点的 x 翻转成 `1 - x`，后面所有代码都在「所见即所得」的
坐标系里工作；handedness 标签也相应翻转。手部骨架小窗因此**不能**再用 CSS 翻转。

**手势分类用 world landmarks。** MediaPipe 的 `worldLandmarks` 是以手心为原点的
米制 3D 坐标，关节角度不受「人离摄像头多远」影响，比屏幕坐标稳定得多。
所有阈值都以「手腕→中指根」的长度做归一化，大手小手通用。

**防抖。** 一个手势要连续 3 帧成立才会被确认（`HandSmoother`），位置用指数平滑；
手离开画面时立刻清空历史，避免手一回来就触发上次攒了一半的「保持」动作。

**装饰球吸附。** 手的位置通过一个显式仿射映射落到树前的一个盒子里，再吸附到
圆锥表面（`tree.snapToSurface`）。吸附半径是冠面的 **1.03 倍再加 0.06**，也就是
稍微在针叶*外侧* —— 贴着冠面挂（×0.92）的话球会被埋进叶子里看不见。
装饰球、彩灯、星星都是树的子节点，因此转动和缩放树时它们会跟着走；
礼物盒则放在 stage 空间，转树的时候它们留在地上不动。

**转盘用相对位移，不用绝对位置。** 最早的版本是 `offset = palm.x - 0.5` 带死区，
结果旋转方向取决于手落在画面的哪半边 —— 举左手自然落在左半边就会**反向**转，
手举在中间则落进死区完全不动（这就是「左手不工作」的原因）。现在改成累加
**这一帧手移动了多少**，于是哪只手、在哪个位置，行为都完全一致，而且可以反复
横扫一直转圈。手数变化时会重新取锚点，否则从「单手的 x」跳到「两手的中点」会抖一下；
每帧位移还做了 clamp，防止识别抖动把树甩飞。

两只手都张开时额外用**两手间距**驱动缩放。中点管旋转、间距管缩放这个分配是因为
两者互不干扰：水平拖动几乎不改变间距，张合几乎不移动中点。

**同一套输入入口。** `experience.addSpin(弧度)` / `addZoom(相对量)` 是公开方法，
手势和鼠标（`ui/pointerControls.ts`）都走它，所以两种输入是叠加而不是互相覆盖。

**彩灯改成竖起拇指。** 原来用握拳，但放松的手很容易被判成握拳而误触发。
拇指手势必须「四指都蜷曲 + 拇指伸直 + 拇指明显高于食指根」，判定要排在 pinch 和
fist **之前** —— 因为按手指数算，竖拇指本身就是一个拳头，谁先匹配谁就会把它吞掉。
「高于」只在屏幕坐标里有意义（world landmarks 是以手心为原点的），所以这一项
单独用屏幕坐标判断。握拳现在不绑定任何动作了。

**拍手看的是速度，不是距离。** 「两只手凑到一起」单手分类器天生看不出来，所以
拍手放在 `gestures/twoHand.ts`：两手掌心间距（用手宽归一化）每帧求导，要求真实的
**合拢速度** > 5.5 手宽/秒，并且两手都是张开的（手掌侧对镜头时分类很不可靠，
所以这里用 `openness` 而不是手势标签）。

**「几只手」也是手势的一部分。** 拍照用双手竖大拇指，而单手竖大拇指是开关彩灯 ——
同一个手型，靠**手的只数**区分。所以 `hold()` 多了一个 `need` 参数：
`'one'` 是**恰好一只**（不是「至少一只」），`'two'` 是至少两只。彩灯用 `'one'`，
拍照用 `'two'`，于是举起第二根拇指的那一刻彩灯那边的计时就被清零，不会连带触发。
一开始用过「双手比取景框」（两手各一个 L、食指与拇指方向互为反向）：几何判据写出来
很漂亮，实际却很难识别 —— 手比成框时食指多半正对镜头，MediaPipe 几乎量不出它的朝向，
所以换成了这个更稳的手型。

**照片随机贴。** 每张照片用拒绝采样挑位置：在墙的范围内随机取点，撞到树的中轴、
已经挂着的照片、或者 HUD 面板盖住的左上角就重抽（最多 40 次，之后允许重叠）。
相框之间还按索引错开了 0.012 的深度，这样万一真重叠也不会 z-fighting。
贴图的 y 范围下界是对着镜头定的：在 z = −14 处，世界 y 低于约 4 的东西在屏幕上
会落到地平线以下，看起来像「立在雪地里」而不是「挂在墙上」。

**画弧看的是轨迹，不是手型。** `gestures/strokes.ts` 里的检测器只吃「每帧一个
指尖坐标」，然后吐一次性事件。它先从缓冲里往回走，找到手**上一次转向**的位置，
只拿这一段作为候选笔画 —— 这样画弧之前随便比划过并不会把这一笔弄脏。然后三个
条件：横向跨度 ≥ 画面宽的 30%、最高点比两端高出 ≥ 7%、**最高点落在行程的
25%~75% 之间**。最后一条是关键：没有它的话一条斜线（最高点在端点）也会被当成弧。
左右两个方向都认，画完有 1.5 秒冷却。

它没有渲染依赖，所以可以直接单测：
`npx tsc src/gestures/strokes.ts --ignoreConfig --outDir /tmp/strokes --module commonjs`
之后喂拱形 / 平线 / 斜线轨迹进去就能验证触发与不触发。

**「清空」要很难误触，而且不碰照片。** 双手都伸出三指、**保持 3 秒** —— 这是全场
最长的一个 hold，因为它唯一的作用是把东西扔掉。照片是这里唯一用户没法重做的东西
（镜头前那一瞬间过去就没了），所以清空场景不动照片墙，只有整体重置（双手食指 / `R`）
才会连照片一起清掉。

**两手靠近时要让单手控制让位。** 合拢双手去拍手，在旧逻辑里同时也是一次
「双掌转盘 + 间距缩放」—— 树会被甩一下再缩小。所以 `TwoHandState.engaged`
（间距 < 3.2 手宽，或拍手后的短暂冷却期内）会直接把转盘和缩放这一整块跳过，
手分开后重新取锚点。

**雪、礼物、烟花都是池化的。** 雪花池按暴雪的量级开到 6400 个，平时只画 2600 个
（`setDrawRange`），拍手时拉满再用 smoothstep 缓慢收回去；没画出来的雪花**也在
继续下落**，否则拉开 draw range 的瞬间会看到一片凝固的雪。礼物雨是三个
`InstancedMesh`（盒身 + 两条丝带），死掉的槽位写一个零缩放矩阵，这样 `count`
恒定、活着的礼物不用重排。

**圣诞老人的 S 形航线也是对着视锥调的。** 路径是一条 `CatmullRomCurve3`，用
`getPointAt`（按弧长采样）保证过弯时速度不忽快忽慢，朝向直接取曲线切线 ——
所以转弯、俯仰、侧倾都是算出来的，模型里没有任何硬编码的航向。
关键在于「多偏才算出画面」完全取决于深度：可见半宽大约是 0.65 × 距相机距离
（相机在 z ≈ 13）。所以掉头点都压在画面外沿一点点：再宽一点圣诞老人会凭空消失好几秒
（第一版就是这样，中段整整 3 秒空镜），再窄一点就不像「飞出去又飞回来」。
贴近那一段压在 z ≈ 3 —— 再近就不是掠过而是糊满镜头了。

**音效和音乐分开两条总线。** 原来的图是 `各声部 → master → destination`，而音乐
开关淡的就是 `master` —— 雪橇铃挂上去的话，关掉音乐连音效一起没了。现在拆成
`musicGain`（开关淡它）和 `sfxBus`，两条都汇到 `out`；混响的 wet 也直接进 `out`，
否则音效的混响尾巴会被音乐开关掐掉。雪橇铃本身是八分音符上的噪声沙锤 + 一句铃声
动机，整体包络在飞行中段（贴近镜头那一下）达到峰值。

**烟花的高度和半径是对着镜头调的。** 相机是固定机位，所以礼花弹的初速、引信时间
和炸开的速度都调到：炸点大约在树顶高度、花的半径约 2.5 个世界单位。再高一点、
再大一点，花就会被画面上沿裁掉 —— 同理圣诞老人的飞行弧线峰值压在树顶略上方。

**照片按「所见即所得」镜像。** 预览窗是 CSS `scaleX(-1)` 镜像的（照镜子的直觉），
所以 `vision/capture.ts` 抓帧时也要 `ctx.scale(-1, 1)`，否则墙上的照片和用户刚才
摆的姿势左右相反。抓帧还会按 4:3 **居中裁切**而不是拉伸。相框位的填充顺序是
「先右后左、先内后外」—— 左上角被 HUD 面板挡着，先填那里的话前几张照片会看不见。

**彩虹是一个平的半环。** 固定机位下真正做一个 3D 彩虹是白费力气（从一个视角看
不出区别），所以 `rainbow.ts` 就是一片面向相机的 `RingGeometry` 半环，颜色在片元
里按**到圆心的半径**算：外侧红、内侧紫，一个 mesh 就覆盖七色、而且没有分色接缝。
两头按极角淡出，让弧脚融进地平线而不是硬生生断掉。颜色还往白色拉了 22% ——
纯饱和的色相配叠加混合看起来像贴纸，不像空气里的光。
（HSV→RGB 那段少写 `abs(...-3)-1` 的话颜色顺序会完全错乱，这是肉眼一看就发现、
但光读代码很难发现的那类 bug。）

**音乐是实时合成的。** `audio/music.ts` 里没有任何音频文件：用 WebAudio 合成
三个声部 —— 三角波 + 微微升高的八度泛音做音乐盒般的铃声（主旋律）、低通滤波的
正弦做和声垫、带通噪声短促包络做雪橇铃。再过一个程序生成的混响（指数衰减的
噪声当脉冲响应）。曲子是《Jingle Bells》（1857，公有领域），16 小节循环。
调度用标准的 WebAudio lookahead 模式：每 60ms 用 `setInterval` 检查，提前 0.6s
把整小节的音符排进音频时钟 —— 不能依赖定时器自身的精度。
浏览器要求音频必须由用户手势启动，所以它搭在「开启摄像头」那次点击上。

**渲染。** ACES Filmic 色调映射 + UnrealBloom。这里最关键的参数是 **bloom 阈值**：
阈值设低（0.6 左右）时受光的雪地和较亮的叶片也会参与发光，整棵树会被洗白；
设到 1.0 之后只有真正自发光的东西（彩灯、星星、亮粉）才会起光晕。
装饰球用 `MeshPhysicalMaterial` 的 clearcoat 配 PMREM 环境贴图出玻璃高光。

**点精灵的尺寸。** 雪花、亮粉、装饰球光晕都是 `Points`，`gl_PointSize` 要用
像素算。`stage.ts` 导出一个共享 uniform `POINT_SCALE`，在 `resize()` 里按
视口高度、FOV 和 devicePixelRatio 更新，所有点着色器都写
`gl_PointSize = 世界直径 * POINT_SCALE / -mv.z`。这样尺寸语义是「世界单位的直径」，
换窗口大小或 Retina 屏都不会变形。雪花额外做了近处淡出和尺寸上限，
否则飘到镜头前的一片雪会糊满整个屏幕。

**树的形体。** 树是 3400 个 instanced 枝叶，一次 draw call，按 9 层「树裙」堆叠：
每层从自己的基部半径向上收窄，所以轮廓是一层层的台阶而不是一个均匀的锥。
关键一点是**每根枝叶从树干附近起，向外长到刚好够到冠面**；反过来让它们从冠面
往外发散，程序化树就会变成一个毛球。每层树裙的外沿还会向白蓝色偏移，形成积雪的边。
